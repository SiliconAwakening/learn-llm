Part 00 · Orientation

先看清这条路：你会得到什么，要付多少

从零训练不是一个动作，是一串可以分别验收的小动作。这一部分只做两件事：把终点写清楚，把成本算清楚。

00.1终点：五个能被别人检验的产物

「学会从零训练」这句话没法验收。把它换成五个产物，每个都能拿给别人看：

  • 一条数据管线：原始文本进去，定长 token 块出来；有去重、有质量过滤、有打包率统计。
  • 一个分词器：自己训的 BPE，能报出压缩比、词表大小、未登录字的处理方式。
  • 一条 loss 曲线：横轴步数，纵轴 train 与 valid；能指出 warmup 段、稳定下降段、过拟合拐点。
  • 一个能生成通顺短句的模型：10M 级，权重文件在本地，能复现生成结果。
  • 一份评测报告：bits-per-byte、固定 prompt 的生成样本、和基线的对比、失败样例分析。

这五件事共同构成「训练」这个词的实际含义。缺任何一件，你都只是跑通了别人的脚本。

为什么是 10M 而不是 1B

10M 参数在 16GB 机器上半天能训完，足够让 loss 从 ln(V) 降到 3 附近、能生成短句。它的价值不在效果，在于整条链路的每一个环节都必须由你亲手接上：数据格式、分词、批次构造、学习率、检查点。这些环节在 1B 模型上完全一样，只是数字变大。

反过来，如果你只有一张 16GB 的卡却想「从零训 1B」，按后面的算力账，需要 463 天。这不是技巧问题。

这份文档不做什么

不讲 transformers 库的 API，不讲怎么调用别人的模型，不讲提示工程。它讲的是：给定一堆文本，如何让一组浮点数学会预测下一个 token。所有环节都用你能读懂的代码实现一遍，框架只是最后一步的加速器。

00.2先记住四个数字，它们能挡掉八成错误决策

训练里有大量「感觉」，但真正决定判断的只有几个常数。这四个先背下来，后面每一节都会回来用。

数字一

ln V —— 随机猜测的 loss

词表大小 V 的对数，就是模型什么都没学会时的交叉熵。V=8000 时是 8.99，V=128000 时是 11.76。任何 loss 都要和它比，否则你不知道「loss 3.2」算好还是烂。

数字二

6 —— 每个参数的每次前向反向

训练总 FLOPs ≈ 6 × N × D。前向 2 次乘加，反向 4 次。这个系数误差在 20% 以内，足够判断可行性。

数字三

ln 2 = 0.693 —— nats 与 bits 的换算

loss 用自然对数，比特用 2 为底。跨分词器比较必须换算成 bits-per-byte，否则词表一变，loss 就不可比。

数字四

20 —— 计算最优的 token/参数比

Chinchilla 结论：每参数 20 个 token 时，给定算力下效果最好。小模型上这个比例完全可达 —— 10M 参数训 2 亿 token 只要 1.1 小时；大模型上本地到不了。知道这点，就不会因为模型「有点笨」而怀疑代码。

这四个数字的实测值来自断言脚本的第一组测试：

为什么基线是 ln V 而不是别的

均匀分布 p=1/V 时，交叉熵 H = −Σ (1/V)·ln(1/V) = ln V。模型初始输出接近均匀（logits 接近 0），所以初始 loss 必然落在 ln V 附近。这也是一个免费的 bug 检查：如果第 0 步 loss 明显偏离 ln V，你的初始化、词表或标签对齐一定有问题。

Part 01 · The Core

训练的本质：预测下一个 token，然后被误差推着走

四个件：一次前向、一个损失、一次反向、一次更新。所有框架、所有规模，都是这四件的重复与加速。

01.1一次前向：形状怎么变，算力花在哪

模型只认整数。给定一段 token id，前向做四件事：查表得到向量、叠若干层变换、投影回词表、算出每个位置对下一个 token 的分数。

形状必须能一路对上

调不通代码时，九成问题出在形状。把每一步的形状写下来，对照着调试：

阶段形状含义
输入 ids[B, T]B 条序列，每条 T 个 token
Embedding[B, T, d]d=320，每个 token 变成 320 维向量
Attention 分数[B, heads, T, T]唯一随 T 二次增长的张量
MLP 中间层[B, T, 832]SwiGLU 的隐藏维，约为 2.6d
logits[B, T, V]V=8000，每个位置对每个词的分数
loss标量B×T 个位置的交叉熵平均

只有一处是平方复杂度：[B, heads, T, T]。T 从 512 涨到 4096，这个张量涨 64 倍。这就是长上下文贵的全部原因，也是所有「高效注意力」论文攻击的靶点。

python
# 打印真实形状，比自己推靠谱
import mlx.core as mx
from model import MiniGPT

m = MiniGPT(vocab=8000, d=320, layers=6, heads=5, max_len=512)
ids = mx.array([[1, 5, 9, 2, 7, 8, 3, 4]])          # B=1, T=8

x = m.emb(ids)                                       # [1, 8, 320]
print("emb     ", x.shape)

print("attn out", a.shape)                           # [1, 8, 320]
logits = m.head(m.norm(x))
print("logits  ", logits.shape)                      # [1, 8, 8000]

为什么 MLP 比注意力参数多

d=320 时，注意力是 4·d² = 409.6K（q、k、v、o 四个矩阵），而 SwiGLU 的 MLP 是 3·d·ff = 798.7K（up、gate、down 三个，ff=832）。容量的主要来源是 MLP，不是注意力。

这条事实的推论：想加能力就加宽/加深 MLP；注意力那边做的优化（GQA、KV 量化）主要是省显存和解码算力，不增加容量。

01.2损失：交叉熵在度量「惊讶程度」

模型对每个位置输出 V 个 logits，softmax 变成概率，然后取正确 token 的概率的负对数。这就是全部。

loss = −ln p(正确 token) 一组位置取平均，就是训练日志里的那个数字

它的信息论含义是：用你预测的分布去编码真实的下一个 token，平均需要多少 nats。预测得越准，需要的编码越短。

三个量必须分清

实测这三个关系（断言脚本第 1 组）：

均匀分布熵 H
5.545 = ln 256
偏斜分布熵 H
1.0098
交叉熵 CE
1.1067
KL 散度
0.0969 = CE − H

关系是 CE = H + KL(p‖q)。H 由数据决定，模型只能压 KL。这意味着存在一个不可逾越的下界：无论模型多大、训多久，loss 都不可能低于数据本身的熵。

这就是「loss 卡在 1.8 不动」的真相

如果数据的下一个 token 本身就带随机性（比如网页里的随机数字、多人对话的不同回复），条件熵就是 1.8，你已经到极限了。此时的正确动作是换数据，而不是调学习率。

判断方法：拿同一批数据，看两个完全不同的模型（比如不同随机种子训出来的）是否都停在同一个值附近。是则为数据熵，否则还有空间。

实现：必须用 log-sum-exp

朴素写法先 exp 再归一，logits 稍大就溢出。正确做法是先减最大值：

python
import numpy as np

def cross_entropy(logits, target):
    # logits: [N, V]，target: [N] 整数。返回平均 nats
    z = logits - logits.max(axis=1, keepdims=True)     # 平移不改 softmax
    logZ = np.log(np.exp(z).sum(axis=1, keepdims=True))
    logp = z - logZ                                     # 每行的 log 概率
    return float(-logp[np.arange(len(target)), target].mean())

# 实测：平移 100 结果不变；平移 1000 直接 nan
# shift=0    → 2.379456
# shift=100  → 2.379456  （fp64 还有余量）
# shift=1000 → nan       （exp 溢出成 inf，inf/inf）

这三个数字来自断言脚本：平移 100 仍精确 与 平移 1000 溢出成 nan 都通过。减最大值不是「优化」，是正确性要求 —— fp16 下阈值低得多，logits 到 20 就可能出问题。

困惑度（perplexity）只是换了单位

ppl = exp(loss)。loss 5.545 对应 ppl 256，意思是「模型在 256 个候选里犹豫」。ppl 好读，但做比值时用 loss 更稳（对数把乘法变加法）。

标签对齐：最常见的静默错误

下一个 token 预测要求 input = ids[:-1]、label = ids[1:]。如果错写成同一个切片，模型会学「复制输入」，loss 会降得异常快然后卡住 —— 因为它学会了恒等映射，而这对预测下一个 token 毫无用处。

自查：随机打乱标签，loss 应该回到 ln V 附近。如果不回，说明有信息泄漏。

01.3梯度：反向传播只是链式法则的调度

没有任何魔法。前向保存每层的中间结果，反向从标量 loss 出发，按逆序把「上游梯度 × 局部导数」乘回去。

为什么是反向模式而不是前向模式

前向模式要为每个输入维度跑一遍，参数量 10M 就要跑 10M 遍。反向模式只跑一遍，因为它利用了一个事实：我们只需要标量对每个参数的导数。代价是要保存激活值。

这个交换很划算，也是 6ND 的来源：前向 2 次乘加/参数/token，反向 4 次（两次算对输入，两次算对权重）。

验证梯度：数值差分是唯一可信的手段

手写反向传播必须验证。方法是对每个参数做中心差分，和解析梯度比相对误差：

python
def gradcheck(f, params, eps=1e-6, tol=1e-6):
    # f(params) 返回 (标量, 梯度 dict)。返回最大相对误差
    _, grads = f(params)                       # 解析梯度
    worst, worst_name = 0.0, ""
    for name, arr in params.items():
        flat = arr.reshape(-1)
        for i in range(min(6, flat.size)):      # 抽查 6 个分量
            orig = flat[i]
            flat[i] = orig + eps
            lp = f(params)[0]
            flat[i] = orig - eps
            lm = f(params)[0]
            flat[i] = orig
            num = (lp - lm) / (2 * eps)
            ana = grads[name].reshape(-1)[i]
            rel = abs(num - ana) / max(1e-8, abs(num) + abs(ana))
            if rel > worst:
                worst, worst_name = rel, name
    return worst, worst_name

# 实测：max_rel_err = 6.08e-08（W1），loss = 2.3795

6.08e-08 这个数量级说明实现是对的。经验阈值：

相对误差判断
< 1e-6正确（fp64 中心差分的合理精度）
1e-4 – 1e-2可疑：多半是某个分支写错了
> 0.1肯定错，或者 eps 选得不合适

eps 不能太小

eps=1e-8 时，loss+eps − loss−eps 会被浮点舍入吃掉，误差反而变大。fp64 用 1e-6，fp32 用 1e-3 左右。如果换 eps 后误差大幅变化，说明你的实现本身没问题，是差分在抖。

反向传播里最容易错的三处

错点 1

softmax 的雅可比

不是对角矩阵。正确形式是 dL/dz = (p − onehot)/B，直接可用，不要自己推。

错点 2

embedding 的累加

同一个 token 出现多次，梯度要累加而不是覆盖。numpy 里用 np.add.at，Python 循环里用 +=。

错点 3

掩码位置的梯度

被 mask 的位置概率为 0，梯度也必须为 0。若用 −inf 直接算，会出现 0 × inf = nan。

01.4参数量与算力：把模型拆成可以数的东西

「这个模型多大」不该靠感觉。给定 V、d、层数 L、头数，参数量是可精确计算的：

N = V·d + L·(4d² + 3·d·ff + 2d) embedding 与输出头共享权重（tied），所以只算一次

代入 V=8000、d=320、L=6、ff=832：

部分算式参数量占比
Embedding（与 head 共享）V·d = 8000×3202.56M26.1%
Attention（每层）4d² = 4×102400409.6K—
MLP（每层，SwiGLU）3·d·ff = 3×320×832798.7K—
Norm（每层）2d640—
合计2.56M + 6×1.209M9.81M100%
python
def count_params(V, d, L, ff, tied=True):
    emb = V * d
    per_attn = 4 * d * d
    per_mlp = 3 * d * ff
    per_norm = 2 * d
    total = emb + L * (per_attn + per_mlp + per_norm)
    if not tied:
        total += emb                       # 独立输出头
    return dict(emb=emb, attn=L * per_attn, mlp=L * per_mlp,
                norm=L * per_norm, total=total)

p = count_params(8000, 320, 6, 832)
print(f"{p['total']/1e6:.2f}M  emb {p['emb']/p['total']:.1%}  "
      f"attn {p['attn']/p['total']:.1%}  mlp {p['mlp']/p['total']:.1%}")
# 9.81M  emb 26.1%  attn 25.0%  mlp 48.8%

5.5 小时（3 TFLOPS）

注意 6ND 里的 N 是「参与计算的参数」

embedding 只被查表，不做矩阵乘，所以严格的前向算力是 2·(N − V·d) + 少量查表开销。小模型里 V·d 占比大，误差也就大（这里差 26%）。

工程上的做法：估算时用 6ND，实际测量时用 token/s 反推。两个数字差 30% 以内都算正常，别为了精确到 1% 浪费时间。

显存：小模型反而不一样

通常说「参数 2 字节（fp16）+ 优化器状态 8–12 字节」。但 10M 模型在 16GB 机器上，显存根本不是约束 —— 权重 20MB，AdamW 状态 80MB。真正的约束是激活值：B×T×d×层数，随序列长度线性增长。

python
# 粗估训练时激活值显存（fp16）
def act_gb(B, T, d, L, bytes_per=2):
    # 每层大致保存 10 个 B×T×d 量级的张量（attn 中间量 + mlp 中间量）
    return B * T * d * L * 10 * bytes_per / 1e9

print(f"{act_gb(4, 512, 320, 6):.3f} GB")     # 0.041 GB
print(f"{act_gb(4, 2048, 320, 6):.3f} GB")    # 0.157 GB

所以 10M 模型可以放心用 batch 16、序列 1024，几乎不占显存。「显存不够」要到 1B 以上、序列 4k 以上才会成为主要矛盾。

本部分验收

  • 给定任意 V/d/L/ff，能心算出参数量在哪个量级（误差 30% 内）。
  • 能解释为什么初始 loss 必然接近 ln V，并用它检查代码。
  • 能写出 log-sum-exp 版的交叉熵，并说明为什么不能直接 exp。
  • 知道反向传播比前向贵一倍，以及贵在哪。

Part 02 · Data & Tokens

数据：把文字变成整数，再把整数排成不浪费的批次

分词器决定了「一个 token 值多少信息」，打包决定了「一步训练喂进多少有效 token」。这两件事都在模型之外，但对最终 loss 的影响不比调学习率小。

02.1BPE：300 次合并，亲手跑一遍

字节对编码的全部逻辑只有一句：找出现频率最高的相邻对，合并成一个新符号，重复 N 次。没有概率，没有神经网络，就是一个带计数的循环。

四十行实现

下面这段是断言脚本里的真实代码，不是伪代码。它在一段 2834 字的训练语料上跑 300 次合并：

python
from collections import Counter

def train_bpe(text, n_merges):
    toks = list(text)                      # 起始：一个字（或字节）一个 token
    merges, hist = [], [len(toks)]
    for _ in range(n_merges):
        pairs = Counter(zip(toks, toks[1:]))          # 相邻对频次
        if not pairs:
            break
        (a, b), freq = pairs.most_common(1)[0]
        if freq < 2:                       # 只出现一次的对合并没有收益
            break
        out, i = [], 0
        while i < len(toks):               # 从左到右贪心替换，不重叠
            if i + 1 < len(toks) and toks[i] == a and toks[i + 1] == b:
                out.append(a + b)
                i += 2
            else:
                out.append(toks[i])
                i += 1
        toks = out
        merges.append((a, b, freq))
        hist.append(len(toks))
    return toks, merges, hist

两处细节决定对错：从左到右贪心替换（不是字符串 replace，否则 aaa 里的 aa 会被重复计数），以及频次小于 2 就停（否则会一直合并只出现一次的长串，把整句塞进一个 token）。

词表大小是一个真实的取舍

词表 V 变大：序列变短（同样的文本占更少位置，注意力更便宜）、每个 token 携带更多信息；但 embedding 和输出层参数按 V·d 线性增长，且稀有 token 的训练样本变少。

10M 模型上 V=8000 时，embedding 占 26.1% 的参数。V 提到 32000，光 embedding 就 10.2M，整个模型被词表吃掉。这就是小模型不该用大词表的原因。

02.2分词器的三条铁律

分词器不是模型的一部分，但它一旦训错，后面所有实验都白做。三条规则，每条都对应一次我踩过的坑。

R1

只在训练集上训分词器

分词器见过验证集的文本，等于验证集泄漏了一部分信息进模型。泄漏的量不大，但它会让你的验证 loss 系统性偏乐观，而且无法事后修正。

验证方法：统计验证集 token 中「训练时从未作为独立 token 出现过」的比例。健康值接近 0；如果验证集里大量出现只在验证集出现过的合并 token，说明分词器提前看到了答案。

R2

特殊 token 必须预留且不可被合并

<|endoftext|> 这类分隔符如果在分词前就拼进文本，会被 BPE 拆成 <、|、e… 一串碎片，模型永远学不到「这里是一篇文档的结尾」。

正确顺序是：先按特殊 token 切分文本 → 各段独立 BPE 编码 → 把特殊 token 的 id 直接插入结果。这样它在任何位置都是一个不可分割的整数。

R3

词表大小要跟模型大小匹配

约束很简单：embedding 参数 V·d 不该超过总参数的一半，否则容量都花在「记住 token 长什么样」上。

10M 配置（V=8000, d=320）：embedding 2.56M，占 26.1%，合理。同样 d=320 配 V=32000：9.2M，占 48%，勉强。配 V=128000：41M，是模型本体（6.9M）的六倍，荒谬。

反过来说，如果你的模型只有 5M 参数，V 就该降到 2000 左右 —— 这也是从零训练时最容易被忽略的一条：照抄大模型的词表，等于给小模型穿大衣。

字符级 vs 子词级：什么时候可以不写 BPE

如果语料是纯中文、目标是 10M 以下的小模型，字符级就够了：中文单字的信息量本来接近一个 token，字符级词表 4000 左右，不需要合并。

反过来，如果语料含英文、代码、URL，字符级会把 function 拆成 8 个 token，序列长度翻几倍，训练成本直接起飞。此时 BPE 不是优化，是必需。

02.3打包：把利用率从 51% 提到 99.9%

变长序列进 GPU/统一内存必须凑成固定形状。两种凑法，成本差一倍。

两种做法的账

实测条件：2000 条样本，长度服从对数正态（均值 210，截断到 30–3000），序列长度 T=1024，批大小 8。

方案步数利用率说明
按批补齐（padding）80650.92%每批 8 条都补到该批最长的那条
序列打包（packing）41199.88%拼成一条长流，切 1024 一块

总 token 数 420375。打包后正好 411 块，几乎不浪费；按批补齐要 806 步，其中一半算力在算 padding。速度差 1.96×，也就是同样的墙钟时间能多训一倍的数据。

节省比 = 效率比 = 99.88 / 50.92 ≈ 1.96× 长度分布越不均匀，补齐浪费越大；全是等长样本时两法等价

打包的代价：跨文档注意力

拼接后，第 411 块里可能前半段是 A 文档的结尾、后半段是 B 文档的开头。因果注意力会让 B 的开头能看到 A 的结尾 —— 这是信息泄漏，模型会学到「上一篇的最后一句话和这一篇的第一句话有关系」这种不存在的规律。

两种修法，按代价排序：

做法代价适用
文档边界处重置注意力（block-diagonal mask）要自定义掩码，多一次分支语料文档短、主题差异大
只在文档间插入 <eos>，不遮几乎零成本语料同质（同类网页、同一本书）

小模型从零训练时，第二种就够：<eos> 让模型知道「新文档开始了」，跨文档那点泄漏在 10M 参数上测不出来。等模型到 100M 以上、验证 loss 卡住时，再回来加 block-diagonal mask。

python
import numpy as np

def pack_stream(ids, seq_len):
    # 把一整条 token 流切成 [n, seq_len] 的块，丢掉尾部不足一块的余量
    n = len(ids) // seq_len
    return np.asarray(ids[: n * seq_len]).reshape(n, seq_len)

def padded_batches(seqs, batch=8):
    # 朴素做法：每 batch 补到该 batch 最长。返回 (块列表, 有效 token 数, 总槽位数)
    out, valid, slots = [], 0, 0
    for i in range(0, len(seqs), batch):
        grp = seqs[i:i + batch]
        L = max(len(s) for s in grp)
        blk = np.zeros((len(grp), L), dtype=np.int64)     # 0 当 pad，真实词表要避开 0
        for j, s in enumerate(grp):
            blk[j, :len(s)] = s
        out.append(blk)
        valid += sum(len(s) for s in grp)
        slots += blk.size
    return out, valid, slots

断言脚本用这两个函数量出上表的数字，并检查了三条：打包利用率 > 99%、补齐利用率 < 60%、加速比 > 1.6×。

pad token 必须从 loss 里排除

补齐位置如果参与 loss，模型会花大量容量去学「预测 pad」。做法是把这些位置的 label 设成 -100（或框架约定的 ignore_index），交叉熵实现里跳过。

自查：打印一步的 loss 与「只算有效位置」的 loss，两者应该一致。如果不一致，说明 mask 没生效 —— 这是打包+补齐混用时最常见的静默 bug。

Part 03 · Architecture

结构：注意力、位置、残差、初始化，四处都不能错

一个 GPT 只有四类零件。每一类都有一个「必须这样做」的理由，理由都能用二十行 numpy 验证。这一部分把四处逐一拆开，最后拼成一个能训的模型。

03.1注意力：为什么必须除 √d，掩码为什么必须在 softmax 之前

注意力就是一个加权平均：用当前 token 的 query 去和所有历史 token 的 key 做点积，得到权重，再用权重加权所有 value。三个细节决定它能不能用。

细节一：点积的方差随维度线性增长

q、k 各分量独立、均值 0、方差 1 时，q·k = Σ qᵢkᵢ 是 d 个独立项之和，每项方差 1，所以点积方差 = d。实测（T=128）：

d点积方差方差 / d若不缩放，logits 的标准差

6463.040.987.9
256253.10.9915.9

d 涨 32 倍，方差涨 31.1 倍；除以 d 之后，三个值都在 1.0 附近。所以缩放因子只能是 √d，且 d 是 head 维度而不是模型维度。

不缩放的后果不是「数值溢出」，而是更隐蔽的梯度消失：logits 标准差 16 时，softmax 输出的分布接近 one-hot（最大值权重 ≈ 1，其余 ≈ 0），反向传播时对非最大项的梯度几乎为 0，注意力学不到「多个来源加权」这件事，只能做硬选择。

scores = Q·Kᵀ / √d_head　　softmax(scores + mask)　　out = A·V √d_head：d_head = d_model / heads，本配置 320/5 = 64

细节二：掩码必须加在 softmax 之前

把未来位置的分数设为 −∞，softmax 之后权重严格为 0，每行仍然归一化到 1。

实测（T=6, d=16）：每行和都是 1.0（差 < 1e-12）；上三角最大值 0.0（严格为零，不是 1e-16）；第 0 行自注意力权重 1.0000，第 1 行 0.1396，第 2 行 0.3618。

很多人会想「先 softmax 再把未来位置清零、再重新归一化，结果不是一样吗」。数学上确实一样 —— 实测最大差异 1.1e-16，即完全等价。但工程上不要这么做：先 softmax 意味着你已经算出了未来位置的概率，只是事后丢掉，多一次归一化和一次除法，而且在 fp16 下多一次误差累积的机会。更重要的是，KV cache 增量解码时未来位置根本不存在，两条路径的代码无法共用。

python
import numpy as np, math

def softmax(x):
    x = x - x.max(axis=-1, keepdims=True)
    e = np.exp(x)
    return e / e.sum(axis=-1, keepdims=True)

def attention(q, k, v, causal=True):
    # q, k, v: [T, d]
    T, d = q.shape
    s = q @ k.T / math.sqrt(d)                    # [T, T]
    if causal:
        s = s + np.triu(np.full((T, T), -np.inf), k=1)   # 上三角（不含对角线）= -inf
    a = softmax(s)
    return a @ v, a

np.triu(..., k=1) 的 k=1 表示从对角线之上第一条开始，保留对角线。写成 k=0 会把当前 token 自己也遮掉，第 0 行变成全 −∞，softmax 输出 NaN —— 这个 bug 的表现是「loss 从第一步就是 nan」，很好定位，但如果你用了 np.nan_to_num 兜底，就会变成更麻烦的「loss 一直 5.5 不降」。

cache 是权重的 4% 可以忽略

所以 10M 模型不需要 GQA、不需要 PagedAttention、不需要量化 KV。先把 MHA 写对，等模型大到 cache 超过权重再回来优化。这也是一条通用原则：优化要等到瓶颈真实出现，否则你只是在给没跑的代码增加复杂度。

03.2位置编码：RoPE 把「相对距离」写进旋转角

注意力本身对顺序完全无感 —— 打乱 token 顺序，点积结果只是跟着重排，模型学到的东西不变。所以位置信息必须显式注入。

绝对位置 embedding 的做法是「第 5 个位置加一个可学习的向量」。问题：训练时最长 512，推理时第 600 个位置没有对应的向量；而且「相隔 3 个位置」这件事在不同位置上要分别学一遍。

RoPE 的做法：旋转

把 d 维向量按相邻两维分成 d/2 组，每组是一个二维平面，用位置 pos 乘上该组的频率作为旋转角：

x'₂ᵢ = x₂ᵢ·cos(pos·θᵢ) − x₂ᵢ₊₁·sin(pos·θᵢ)
x'₂ᵢ₊₁ = x₂ᵢ·sin(pos·θᵢ) + x₂ᵢ₊₁·cos(pos·θᵢ)　　θᵢ = 10000^(−2i/d) 低频维度转得慢（管长距离），高频维度转得快（管相邻区分）

为什么它给出相对位置

关键性质：两个旋转过的向量的点积，只依赖它们的相对角度。

⟨R(a)q, R(b)k⟩ = ⟨q, R(b−a)k⟩ 左边含绝对位置 a、b，右边只含 b−a

实测（d=16，同一对向量）：Δ=3 的四组位置 (0,3) (5,8) (20,23) (40,43)，点积全部是 −0.4847623226，极差 0。Δ=10 的点积则明显不同。

三个必须知道的数字

性质实测值含义
旋转保持范数‖R(x)‖ = ‖x‖，差 < 1e-12不改变向量的能量，只改方向
点积能量不随距离衰减RMS 4.31 / 3.97 / 3.86 / 5.51（Δ=1/4/16/32）≈ √d = 4，max/min = 1.43
最高频维度周期6.283 tokenθ₀ = 1 rad/token，转一圈 2π

第二行是 RoPE 与「训练出来的相对位置偏置」的关键区别：无论两个 token 隔多远，注意力分数都不会因为距离被系统性压低。衰减完全交给模型自己学。好处是长距离依赖不被结构性地惩罚；代价是模型必须自己学会「太远的东西不可信」，而这需要数据。

第三、四行说明相位回绕：最高频维度每 6.283 个位置转回原点，实测旋转 2π 后的偏差是 0（< 1e-12）。所以超出周期的位置会产生歧义 —— 位置 0 和位置 6 在第 0 维上完全一样，只能靠其他低频维度区分。d=16 时最低频维度能撑到近 2 万个位置；真实模型 d_head=64 时更低频，周期再长十倍以上。这也是「RoPE 外推到长上下文需要重设 base（NTK 缩放）」的根源。

python
import numpy as np

def rope(x, pos, base=10000.0):
    # x: [T, d]，d 为偶数；pos: [T] 的整数位置
    T, d = x.shape
    half = d // 2
    theta = base ** (-np.arange(half) / half)      # (d/2,) 各组的基础频率
    ang = pos[:, None] * theta[None, :]            # (T, d/2) 每个位置每组的角度
    cos, sin = np.cos(ang), np.sin(ang)
    x1, x2 = x[:, :half], x[:, half:]              # 前半与后半配对旋转
    return np.concatenate([x1 * cos - x2 * sin,
                           x1 * sin + x2 * cos], axis=1)

注意配对方式：这里用的是「前后半配对」（x[i] 与 x[i+d/2]），不是相邻配对（x[2i] 与 x[2i+1]）。两种实现等价（只是维度排列不同），但必须与推理时的实现一致，否则训出来的模型一加载就全乱。这也是自己实现时最容易踩的坑之一。

RoPE 要作用在 q 和 k 上，不能作用在 v 上

位置信息影响的是「谁该注意谁」（q·k），而 v 是被搬运的内容。给 v 加旋转等于把内容本身随位置改变，模型要花容量去抵消这个变换。

另外，q 与 k 必须用同一个 theta，且位置下标必须是序列内的绝对偏移。打包多条样本进一个序列时，第二条样本的位置要从 0 重新开始还是接着数？答案是接着数（因为它们在同一个注意力窗口里），但如果你加了 block-diagonal mask，就必须从 0 重数。选一种，别混。

03.3残差与归一化：为什么每一层都在放大信号

残差连接 x = x + f(x) 让梯度能直接回传，这是训练深层网络的前提。但它同时带来一个副作用，很多人不知道：它让方差随层数指数增长。

算一遍

假设每层输出 f(x) 的方差与输入相同（都是 1），且两者近似独立：

Var(x + f(x)) = Var(x) + Var(f(x)) = 1 + 1 = 2 100 层后：2¹⁰⁰ ≈ 1.3×10³⁰，标准差 ≈ 1.1×10¹⁵

实测（d=256，100 层堆叠，输入 std=1）：

初始化方案第 100 层 std现象
固定 std=0.052.34e−10指数衰减到 0，梯度也没了
1/√fan_in（方差保持），无残差1.031稳定 —— 这是对照组
√(2/fan_in)（He），无残差9.79e14每层放大 √2，100 层后爆掉
1/√fan_in，有残差9.47e14即使初始化正确，残差也会把它推到同一量级

最后两行数字巧合地接近，但原因不同：He 是每层乘 √2，残差是每层加一次自身。两者都指向同一个结论：「初始化对了」不足以让深层网络稳定，必须再加一层控制。

三种控制手段

1

Pre-LN：把归一化放在子层输入

原版 Transformer 是 Post-LN：x = LN(x + f(x))，要求 warmup 很小心，否则早期梯度爆炸。现代模型全部改成 Pre-LN：x = x + f(LN(x))。

代价是主干通路的方差仍然会随层数累积（因为 LN 在支路上，不在主路上），所以最后必须加一个 final norm 把尺度拉回来。收益是训练极其稳定：Pre-LN 几乎不需要 warmup 也能起步，warmup 变成「优化需要」而不是「不发散的需要」。

2

RMSNorm 代替 LayerNorm

LayerNorm 要减均值、除标准差，再做仿射。RMSNorm 只除均方根，不减均值：

y = x / √(mean(x²) + ε) · g

少一次归约、少一组 bias，实测在这些模型上效果无差别。省下的算力在归一化这个位置约 10%–15%，绝对值不大，但免费。

3

残差支路缩放：1/√(2L)

把每个子层的输出乘一个系数 1/√(2L)（L 是层数），这样 2L 个残差支路（每层注意力 + MLP 两个）的总方差贡献正好是 1，主干方差保持在初始量级。

GPT-2 的做法更省事：只把每个块的输出投影权重初始化为 0，等价于「训练开始时所有块都是恒等映射」，让模型从浅到深自己长出来。10M 规模上两者都能用，我选后者 —— 一行初始化，不用改前向。

python
import mlx.core as mx
import mlx.nn as nn

class Block(nn.Module):
    def __init__(self, d, heads, ff):
        super().__init__()
        self.n1 = nn.RMSNorm(d)
        self.n2 = nn.RMSNorm(d)
        self.attn = CausalSelfAttention(d, heads)
        self.mlp = SwiGLU(d, ff)
        # 关键：残差支路的输出投影零初始化
        self.attn.proj.weight = mx.zeros_like(self.attn.proj.weight)
        self.mlp.down.weight = mx.zeros_like(self.mlp.down.weight)

    def __call__(self, x, mask=None):
        x = x + self.attn(self.n1(x), mask=mask)     # Pre-LN
        x = x + self.mlp(self.n2(x))
        return x

零初始化的效果可以直接观测：第 0 步的 loss 应精确等于 ln V（模型输出全零 logits → 均匀分布）。如果第 0 步 loss 明显高于 ln V，说明初始化没做对，此时不要去调学习率。

03.4初始化：一个公式推到底

上面已经看到，初始化的目标是让每层输出的方差等于输入方差。推导只有两行。

设 y = Wx，W 的元素独立、均值 0、方差 σ²，x 的元素独立、均值 0、方差 1，维度 fan_in = n：

Var(yᵢ) = Σⱼ Var(Wᵢⱼ) · Var(xⱼ) = n·σ² 要让它等于 1，就得 σ² = 1/n，即 σ = 1/√fan_in

两条曲线的含义

平的那条（1/√fan_in）是目标；向下那条（固定 0.05）是「所有层都没信号」，模型等价于只有最后一层在工作，loss 卡在某个值再也不动；向上那条（He）是「所有层都饱和」，激活值进入 softmax 的极端区域，梯度为 0。

一个命名上的坑：Glorot（Xavier）的原始形式是 √(2/(fan_in+fan_out))，在 fan_in = fan_out 的方阵上就是 √(2)·(1/√fan_in) —— 比这里高 √2 倍，所以它属于上表中「每层放大 √2」那一类。上表用的是严格保持方差的 1/√fan_in。看到「Xavier 初始化」时，先确认它指的哪一个，两种实现在 100 层后能差 30 个数量级。

三种失败模式的表现完全不同，这是排查时的第一分诊表：

现象第 0 步 loss几十步后原因
信号消失≈ ln V几乎不动初始 std 太小
信号爆炸>> ln V 或 nannan / inf初始 std 太大 / 无归一化
正常= ln V稳定下降—

第一行值得强调：loss 精确等于 ln V 有两种截然不同的原因。一种是初始化正确、模型还没学到东西（正常）；另一种是信号在前向中衰减到 0，logits 恒为 0，永远输出均匀分布（卡死）。区分方法：看几十步后 loss 是否下降，以及打印某一层激活的 std。

python
import numpy as np

def init_std(fan_in, fan_out, scheme):
    if scheme == "xavier":
        return np.sqrt(2.0 / (fan_in + fan_out))
    if scheme == "he":
        return np.sqrt(2.0 / fan_in)
    if scheme == "lecun":
        return np.sqrt(1.0 / fan_in)
    raise ValueError(scheme)

# 自检：100 层、d=256、线性、无激活
def probe(std_fn, layers=100, d=256, residual=False, seed=0):
    rng = np.random.default_rng(seed)
    x = rng.normal(0, 1, (64, d))
    for _ in range(layers):
        W = rng.normal(0, std_fn(d), (d, d))
        h = x @ W
        x = x + h if residual else h
    return float(x.std())

print(probe(lambda n: 0.05, residual=False))          # 2.3e-10  消失
print(probe(lambda n: 1 / np.sqrt(n), residual=False))  # 1.031   刚好
print(probe(lambda n: np.sqrt(2 / n), residual=False))  # 9.8e14  爆炸

03.5拼成一个模型：参数逐个对账

下面是把前四节拼起来的完整模型。配置：V=8000、d=320、L=6、heads=5、ff=832、T=512。

python
import mlx.core as mx
import mlx.nn as nn
import math

class CausalSelfAttention(nn.Module):
    def __init__(self, d, heads):
        super().__init__()
        assert d % heads == 0
        self.h, self.dh = heads, d // heads
        self.qkv = nn.Linear(d, 3 * d, bias=False)
        self.proj = nn.Linear(d, d, bias=False)

    def __call__(self, x, mask=None):
        B, T, _ = x.shape
        q, k, v = mx.split(self.qkv(x), 3, axis=-1)
        # [B,T,d] -> [B,h,T,dh]
        sh = lambda t: t.reshape(B, T, self.h, self.dh).transpose(0, 2, 1, 3)
        q, k, v = sh(q), sh(k), sh(v)
        s = (q @ k.transpose(0, 1, 3, 2)) / math.sqrt(self.dh)   # [B,h,T,T]
        if mask is not None:
            s = s + mask
        a = mx.softmax(s, axis=-1)
        o = (a @ v).transpose(0, 2, 1, 3).reshape(B, T, -1)      # [B,T,d]
        return self.proj(o)

class SwiGLU(nn.Module):
    def __init__(self, d, ff):
        super().__init__()
        self.up = nn.Linear(d, ff, bias=False)
        self.gate = nn.Linear(d, ff, bias=False)
        self.down = nn.Linear(ff, d, bias=False)

    def __call__(self, x):
        return self.down(nn.silu(self.gate(x)) * self.up(x))

class MiniGPT(nn.Module):
    def __init__(self, vocab=8000, d=320, layers=6, heads=5, max_len=512):
        super().__init__()
        ff = int(8 / 3 * d / 32) * 32          # SwiGLU 要按 3 个矩阵折算，ff ≈ 2.67d
        self.emb = nn.Embedding(vocab, d)
        self.blocks = [Block(d, heads, ff) for _ in range(layers)]
        self.norm = nn.RMSNorm(d)
        self.head = nn.Linear(d, vocab, bias=False)
        self.max_len, self.d = max_len, d

    def causal(self, T):
        return mx.triu(mx.full((T, T), -1e9), k=1)

    def __call__(self, ids):
        T = ids.shape[1]
        x = self.emb(ids)
        mask = self.causal(T)
        for b in self.blocks:
            x = b(x, mask)
        return self.head(self.norm(x))         # [B, T, V]

两处需要解释：ff = int(8/3·d/32)·32 是因为标准 FFN 用 4d，而 SwiGLU 有三个矩阵，为了参数持平要乘 2/3，得 8/3·d；再向上对齐到 32 的倍数，原因是矩阵乘在小硬件上对维度对齐敏感。本配置 d=320 → 853 → 对齐到 832。

参数逐个对账

公式 N = V·d + L·(4d² + 3·d·ff + 2d)，head 与 embedding 共享权重（tied）。

项算式参数占总比

每层 MLP（up + gate + down）3 × 320 × 832798,72048.8%

三个数字要记住：embedding 占 26.1%（小模型的特征，大模型这个比例降到 1% 以下）、MLP 占 48.8%（容量的主要来源）、注意力只占 25.0%。

由此得到一条实用推论：想加容量，先加 MLP 宽度或层数，不要加 heads。heads 从 5 加到 10，参数量不变（d 固定），只是把同样的维度切成更多份，表达能力变化有限，反而让每个 head 的维度变小（64 → 32），单 head 能表达的模式变简单。

每 token 6N FLOPs 的来历

前向：每个参数参与一次乘加 = 2 FLOPs，共 2N。反向：算对输入的梯度 2N，算对权重的梯度 2N，共 4N。合计 6N。

本配置：6 × 9.81M = 58.9M FLOPs/token。注意这个式子不含注意力的 T² 项 —— 因为 6N 只算矩阵乘的权重部分。T 很大时（T > 6d 左右），注意力里的 Q·Kᵀ 和 A·V 会反超，需要单独加 12·L·T·d。本配置 T=512、d=320，12×6×512×320 = 11.8M，是 6N 的 20%，还不能忽略，但也没到主导。

Part 04 · Dynamics

动力学：优化器、学习率、裁剪、稳住、采样

结构决定模型能表达什么，动力学决定它能不能走到那里。这一部分用可数的步数、可测的梯度范数，把「调参」变成「读数」。

04.1优化器：同一个问题，6906 步 vs 249 步

「Adam 比 SGD 好」这句话没有信息量。有信息量的是：在什么条件下好多少倍，代价是什么。用一个能算出精确解的问题量一遍。

测试设置

目标函数 f(x) = ½·xᵀAx，A = diag(linspace(1, κ, 10))，最小值在原点。κ 是条件数 = 最大曲率 / 最小曲率。取 κ=1000，初值固定（保证可复现），停止条件 ‖g‖ < 1e-3。

为什么用这个而不是真模型？因为真模型上你无法知道「最优解在哪、还差多远」，只能看 loss 曲线猜。二次函数上每一步的梯度范数就是「离最优有多远」的精确度量。

优化器学习率到达 ‖g‖<1e-3 的步数相对 SGD额外显存

Momentum（μ=0.9）1e−363011.0×1× 参数
Adam（β=0.9/0.999）5e−224927.7×2× 参数

SGD 的学习率不是随便取的：1/L_max 是理论稳定上限，再大就发散。所以 SGD 的步数里有一半是被条件数逼出来的 —— 它在最陡的方向上不敢迈大步，于是在最平的方向上走得极慢。这就是 κ 的含义。

Adam 为什么对条件数不敏感

Adam 把每个坐标的梯度除以它自己的历史均方根：更新量 = lr · m̂ / (√v̂ + ε)。对每个坐标，这个比值大致是 ±1 乘以 lr —— 曲率大的坐标自动缩小步长，曲率小的自动放大，条件数被逐坐标归一化掉了。

验证方式：把 κ 从 1000 降到 100，同样设置再跑：

比值
1.17× 条件数差 10 倍，步数只差 17%

同一条件下 SGD 会把步数差出十倍。这条结论的实用价值：如果你的模型对学习率极其敏感、换个种子就发散，很可能是某个方向的曲率远大于其他方向 —— 不是 lr 设错了，是结构或数据里有尺度不一致（比如某一层输入未被归一化）。

Momentum+40 MB 动量1.1×lr, μ

10M 模型上 80MB 无所谓。到 1B 模型上这是 16GB，等于把「能不能在 16GB 卡上放下」的答案从能变成不能 —— 这也是 Adafactor、8-bit Adam、CPU offload 这些技术存在的唯一理由。

从零训练小模型的选择：直接用 AdamW，不要纠结。它省掉的调试时间（反复找 SGD 的 lr 和 momentum）远大于它多花的显存。等模型大到显存吃紧，再考虑换。

AdamW 里的 W 是 weight decay，不能省

Adam + L2 正则和 AdamW 不等价：L2 会把惩罚项加进梯度，再被 Adam 的逐坐标归一化扭曲掉（大权重的惩罚被缩小，小权重的被放大）。AdamW 把衰减直接作用在权重上：w ← w − lr·(m̂/(√v̂+ε)) − lr·λ·w。

小模型上 λ=0.1 是常见起点。判断标准：训练 loss 与验证 loss 的差距。差距大就加 λ，差距小或欠拟合就减。

04.2学习率调度：warmup 不是为了「慢慢来」

学习率先升后降，几乎成了默认操作。但两个阶段的理由完全不同：warmup 是为了修正一个偏差，cosine 衰减是为了收敛。

warmup 的真实原因：Adam 的偏差修正

Adam 第 1 步时 m = 0.1g、v = 0.001g²，经过偏差修正：

m̂ = m/(1−0.9¹) = g　　v̂ = v/(1−0.999¹) = g²
更新量 = lr · g / (|g| + ε) ≈ lr · sign(g) 第 1 步的实际步长是 lr 乘以每个坐标的符号，与梯度大小无关

这意味着第一步在每个坐标上都迈出完整的 lr，即使那个坐标的梯度只有 1e-6。参数离初值有 0.02 的差距时，lr=6e-4 的第一步就走掉 3%，而 Adam 会继续按这个幅度走几十步直到 v 的估计稳定下来。warmup 就是把这几十步的幅度压住。

实测的调度采样点（base=6e-4, warmup=100, total=2000, min_ratio=0.1）：

第 0 步是 6e-6，第 99 步到峰值，之后严格不增。注意 cosine 的形状：前 20% 的步数只降了 2.5%，后 20% 降了 76%。这不是缺陷，是 cosine 的特性 —— 大部分训练时间花在高学习率上（充分探索），收尾阶段快速降温（固化成果）。

python
import math

def lr_at(step, total=2000, warmup=100, base=6e-4, min_ratio=0.1):
    if step < warmup:                                  # 线性升温
        return base * (step + 1) / warmup
    p = (step - warmup) / max(1, total - warmup)       # 0 → 1
    return base * (min_ratio + (1 - min_ratio) * 0.5 * (1 + math.cos(math.pi * p)))

参数怎么定本配置错了会怎样
total由算力预算倒推，不中途改2000改 total 等于改曲线，之前的学习率历史全废
base二分搜索：能跑不炸的最大值6e−4太大学不会，太小走得慢
warmup总步数的 2%–5%100（5%）太短早期震荡，太长浪费步数
min_ratio0.1，别降到 00.1降到 0 会让最后几步几乎不动，白训

「total 不能中途改」这条经常被违反：想加训就重启，曲线从低处重新爬升，效果比一次性训到位差。如果一定要续训，正确做法是接着用当前进度算 lr，而不是重置 cosine。

04.3梯度裁剪：保险丝，不是旋钮

裁剪的公式是 g ← g · min(1, c/‖g‖)。注意是整体缩放，不是逐元素 clamp —— 逐元素会把梯度的方向改掉，整体缩放只改长度，方向不变。这个区别在裁剪频繁时非常明显。

先量一次：阈值 c 到底会影响多少步

这组数字的意义：如果 c=1.0 在一半以上的步上都生效，那它就不是「防止爆炸」，而是「给模型换了一套梯度」，学习率的语义也变了（有效步长变成 c 乘以方向）。很多教程照抄 clip=1.0，但在小模型上这个值可能过分激进。

python
import math

def clip_by_global_norm(grads, c):
    # grads: dict[name -> array]，原地缩放
    total = math.sqrt(sum(float((g ** 2).sum()) for g in grads.values()))
    scale = min(1.0, c / (total + 1e-12))
    if scale < 1.0:
        for k in grads:
            grads[k] = grads[k] * scale
    return total, scale

实现要注意两点：用平方和的 sqrt，不要用 L1（L1 让范数随参数量线性增长，换模型就得重调 c）；先算全局再缩放，不要边算边改（否则后半部分的范数是缩放后的）。

训练日志里必须打的五个数

step lr train_loss gnorm clip_frac（最近 N 步被裁剪的比例）。

只有 loss 一条曲线，你只能知道「出问题了」。加上 gnorm 能区分「梯度爆炸」和「数据有问题」；加上 clip_frac 能知道裁剪配置是否合理。这五个数是排查一切训练问题的起点，从第一步就该打。

04.4不稳的时候，按这张表查

训练出问题只有四种表现：loss 变 nan、loss 突然尖峰后恢复、loss 突然尖峰后不恢复、loss 一直不动。每种对应有限的几个原因，按顺序查，三分钟能定位。

一、loss 直接 nan

检查正常值异常说明
第 0 步 loss= ln V（本配置 8.99）NaN → 前向就有 inf，查 mask 是否把整行设成 −inf
logits 的 max个位数上千 → 权重初始化错，或某层未归一化
loss 计算里的 log先减 max没减 → exp 溢出成 inf，inf/inf = nan
学习率≤ 1/L_max 量级过大 → 第一步就飞出去

最常见的一条：因果掩码写错，第 0 行全被遮住，softmax 输出 0/0。检查方法是打印 a[0]（第一行注意力权重），应该只有第一个元素是 1，其余是 0。

二、尖峰后恢复

表现：loss 从 3.2 跳到 9.0，几十步后回落到 3.1。这通常是遇到了一个异常样本（超长、乱码、格式突变），或者累积的动量把它推离了最优点。

处理：不用处理。只要恢复了，它就是一阶信息，不是错误。要做的是记录下来 —— 如果同一个 step 反复出问题，去看那个 batch 的数据。

三、尖峰后不恢复（发散）

可能原因三分钟验证处理
学习率过高把 lr 除以 3 重跑前 200 步确定 base lr 后重训
某层激活爆炸打每层 std，找第一个超过 100 的查该层的归一化是否漏了
fp16 溢出换 bf16 或 fp32 重跑同一段用 bf16；或加 loss scaling
数据里有 inf/nan扫一遍输入，找非有限值清洗数据

第二行是最有价值的一行：逐层打印激活 std，找第一个越界的层。这比调学习率快十倍，因为它直接指向结构错误（少了一个 norm、某个矩阵没初始化、残差接错位置）。

四、loss 不动

分三种，靠第 0 步 loss 区分：

第 0 步 loss几十步后原因验证
= ln V仍是 ln V信号在前向中衰减到 0打第 1 层和第 L 层的激活 std
= ln V缓慢下降正常，只是慢lr 是否太小；warmup 是否过长
< ln V 但从不下降不动标签对齐错（在学复制输入）随机打乱标签，loss 应回到 ln V

第三行是隐蔽 bug：input = ids[:-1]、label = ids[:-1]（本该是 [1:]）时，模型学恒等映射，loss 会从 8.99 快速降到 1 左右然后卡住。看起来像「学得很快」，实际什么都没学到。验证方法只有一条：把标签随机打乱重训，如果 loss 还能降到 1，说明标签泄漏。

bf16 与 fp16 的选择

Apple Silicon 和现代 GPU 都支持 bf16。bf16 的指数位与 fp32 相同（8 位），尾数只有 7 位；fp16 相反（5 位指数、10 位尾数）。

训练的瓶颈是指数范围，不是精度 —— 梯度可能小到 1e-8 也可能大到 1e5，fp16 的范围撑不住，必须配 loss scaling；bf16 天然够。代价是 bf16 的有效精度低（约 3 位十进制），单步更新量小于权重本身时会被舍入掉。缓解办法：参数用 fp32 存，前向/反向用 bf16 算（混合精度），mlx 和 torch 都是默认行为。

04.5采样：温度、top-p，和「有效候选数」

训练好的模型输出的是分布，不是文字。选哪个 token 决定了生成风格，这个选择比大多数人以为的重要。

温度：除以一个数，改变整个形状

p = softmax(logits / T)。T<1 让分布更尖，T>1 更平。实测（V=50，logits 服从 N(0,3) 且有一个被抬到 6.0）：

「有效候选数」= e^H 是最值得记的一个量。它把「温度」这个抽象参数翻译成「模型实际在多少个选项里挑」。T=0.3 时只有 2.6 个候选 —— 所以你看到的是「差不多每次都一样」；T=1.5 时有 16.9 个，其中大部分是模型认为可能但实际不通的。

对数关系值得注意：T 从 0.3 到 1.5 涨 5 倍，候选数从 2.6 涨到 16.9（6.5 倍），熵从 0.97 到 2.83（2.9 倍）。温度对候选数的影响接近线性，对熵是对数 —— 所以「调温度」在低温度区间的效果远比高温度区间明显。

top-p：把尾部直接砍掉

按概率从大到小累加，达到 p 就停，剩下的全部丢弃并重新归一化。同一个分布上：

top-p = 0.8
保留 7 / 50
top-p = 0.9
保留 10 / 50
top-p = 0.95
保留 12 / 50

top-p 相对 top-k 的好处是自适应：分布尖的时候自动只留几个，分布平的时候自动多留。top-k=10 在分布尖的时候会强行带进 7 个几乎不可能的 token，在分布平的时候又砍掉了合理的候选。

python
import numpy as np

def sample(logits, temp=1.0, top_p=0.95, rng=None):
    rng = rng or np.random.default_rng()
    z = np.asarray(logits, dtype=np.float64) / temp
    z = z - z.max()
    p = np.exp(z)
    p = p / p.sum()
    if top_p < 1.0:
        order = np.argsort(-p)
        cum = np.cumsum(p[order])
        k = int(np.searchsorted(cum, top_p) + 1)      # 至少留 1 个
        keep = np.zeros_like(p)
        keep[order[:k]] = p[order[:k]]
        p = keep / keep.sum()
    return int(rng.choice(len(p), p=p))

两个实现细节：searchsorted 之后要 +1，否则 p=0.9 恰好落在边界上时可能一个都不留；重归一化必须做，否则 rng.choice 会报「概率和不为 1」。

评测生成质量时，先固定采样参数

温度从 0.7 改到 0.8，生成结果的差异可能比「换了模型」还大。比较两个模型时，采样参数必须完全一致，并且写进报告。

更严格的做法：报告 greedy（T=0） 和 T=0.7, top-p=0.9 两组结果。前者可复现、便于对比；后者反映真实使用体验。只报一组都有偏差。

很多人以为训完看 valid loss < ln V 就算成功。上面这条曲线说明：valid loss 可以远高于 ln V，而模型在训练集上 100% 正确。

它自己带三条断言（初始 loss ≈ ln V、valid 最低点在前 20%、末尾 valid 回升），不满足就直接报错退出。这三条就是「链路通」的定义。

05.3训练循环：五件事，缺一件就要返工

一个能用的训练循环不是 for step in range(N): loss.backward(); opt.step()。差五件事，每一件缺了都会在某个时刻逼你重跑。

1

学习率调度

lr_at(step) 按当前 step 算，不是初始化时算一次。续训时尤其重要 —— 要用「当前 step 在原来那条曲线上对应的 lr」，不是重头开始。

2

梯度裁剪

算全局范数，超过阈值就整体缩放。阈值设在正常梯度的 p99 的 2–3 倍，平时不生效，出尖峰时兜住。

3

日志五件套

step、lr、train、valid、gnorm，加一列 clip（是否触发）。只有 loss 一条曲线时你只能知道「出问题了」；有 gnorm 才能区分「梯度爆炸」和「数据异常」。

4

检查点要存优化器状态

只存权重，续训等于重新开始（Adam 的 m、v 从零起步，前几十步的更新幅度会突然变大）。必须存 weights + m + v + step 四样。

5

早停要记录最优那一步，不是最后一步

验证损失最低的那个检查点才是有用的模型。最后的检查点几乎必然过拟合（除非数据量远超参数量）。实现上：每次评估若 valid 改善就另存一份 best.npz。

评测：把「好像变好了」换成能比较的数字

raw loss 不能跨分词器比较，也不能说明模型会不会说话。这一部分给出两把尺子：每字节比特数用来跨分词器比，消融账本用来归因每一次改动。

06.1bits-per-byte：让两个分词器站到同一把尺子上

一个具体的困境：字符级模型验证 loss 5.875，子词级模型 5.974。哪个更好？

看起来字符级赢了 1.7%。答案是完全相反：子词级好了 20.4%。原因是两个 loss 的单位不同 —— 一个在「每字符」上平均，一个在「每 token」上平均，而一个子词 token 覆盖的字比一个字符多。

换算公式

bpb = loss / ln 2 / (每 token 的字节数) loss 是 nats/token；除以 ln 2 = 0.6931 换成 bits/token；再除以 bytes/token 得到 bits/byte

为什么用「字节」做公共分母？因为字节是文本的客观度量，与分词器无关。同一段中文，UTF-8 编码后字节数固定（一个汉字 3 字节），不管你怎么切 token，总字节数不变。所以 bpb 只反映「模型对这段文本的压缩能力」。

这个量的信息论含义很干净：bpb = 2 意味着模型需要 2 比特来表示原文的每一个字节。一个字节有 256 种可能，它的熵上限是 8 比特，所以 bpb 的理论范围是 0 到 8。当前最好的大模型在英文上能到 0.6 左右。

三条常见误用

一、用 loss 比较不同词表大小的模型。词表从 8k 提到 32k，loss 会普遍更低（序列变短、预测变容易），但这不代表模型更强。必须换成 bpb。

二、忘记「每 token 字节数」要从训练集统计。应该用训练语料的 总字节数 / 总 token 数，不是验证集的（会有波动），更不是估的。

三、把 bpb 和「压缩率」搞混。压缩率是 token 数 / 字节数（本例字符级 0.335、BPE 0.262），bpb 是 loss 换算后的比特数。前者描述分词器，后者描述模型。

什么时候 bpb 也不够

bpb 只衡量「预测下一个 token 的能力」，它不区分「模型学会了语法」和「模型背下了语料」。三个补充指标：

指标怎么算能发现什么
train/valid bpb 差同一条命令分别算过拟合程度。本例 gap 在 overfit 演示里是 8.375 nats
不同领域上的 bpb按来源分桶，各算一次模型偏科：某一类文本 bpb 特别高
生成样本的人读通过率抽 50 条，人工判「通顺/不通顺」bpb 低但生成乱码（少见，但存在）

第三行不能自动化，但也不能省。bpb 低而生成质量差的组合确实存在 —— 通常是因为模型对高频模式过拟合，对长程结构一无所知。抽 50 条读一遍，十分钟，能发现自动指标发现不了的问题。

06.2评测协议：五条规则，否则数字没有意义

评测的难点不是算指标，是让指标可比。同样一个模型，换一组采样参数，生成质量的差异可以超过换模型。五条规则，每条都是为了消除一个变量。

R1

测试集完全不参与任何决策

调超参看的叫验证集，最后报的才叫测试集。两者必须是不同的数据，而且测试集只在最后一次用。

违反的代价：你根据测试集调了三次超参，报告里的数字就带上了「在测试集上选过模型」的乐观偏差。这个偏差在小测试集上可以到 5% 以上，足以让「改进」变成噪声。

R2

采样参数固定并写进报告

比较生成质量时，temperature、top_p、max_tokens、是否 greedy，全部固定。Part 04 实测过：温度 0.3 时有效候选数 2.6，温度 1.5 时 16.9，差 6.5 倍。

报告格式建议：greedy (T=0) 和 T=0.7, top-p=0.9 两组都给。前者可复现，后者反映真实体验。

R3

报相对差，不报绝对值

「bpb 2.258」这句话单独没有意义 —— 它依赖语料、分词器、上下文长度、验证集大小。有意义的是「bpb 从 2.836 降到 2.258，降 20.4%」。

绝对值的唯一用途是和自己历史版本比。跨项目比绝对值几乎总是错的。

R4

跑三个种子，报中位数

小规模训练的种子噪声很大：初始化、数据顺序、dropout 都会变。单次实验的结论只对它自己成立。

做法：同一个配置跑 3 个种子，报中位数和极差。如果两个配置的差距小于极差，那这个差距不可信，不要写进结论。

R5

至少一个非 loss 指标

loss 只看「下一个 token 的平均表现」。至少补一个：困惑度分布（不是均值）、按位置分桶的 bpb（前 10 个 token vs 后 10 个）、或人工通顺率。

按位置分桶特别有用：如果前几个 token 的 bpb 远高于后面，说明模型不擅长「开头」，这通常意味着 BOS 处理有问题。

随机基线的 bpb 怎么算

随机模型输出均匀分布，loss = ln V（单位 nats/token）。换算：

bpb_random = ln V / ln 2 / (bytes_per_token)

本例 6.227 / 0.6931 / 2.854 = 3.148。任何模型报 bpb 时都应该带上这个基线，否则读者无法判断它是真学到了还是没超过瞎猜。

消融最常犯的三个错

一、拿不同步数的结果比。「A 训了 2000 步到 bpb 3.1，B 训了 1000 步到 3.2，所以 A 更好」—— 这句无效，B 可能只是没训够。要么同步数，要么同算力（6ND 相等）。

二、拿不同数据量的结果比。加了数据带来的改善，和第 1 项改动的改善，必须分开测。

三、报最优 checkpoint 而不是固定步数的 checkpoint。「最优」本身是一个在验证集上做过的选择，会让每个变体都朝有利于自己的方向偏。消融时应该固定步号取指标，只在最终报告里用最优 checkpoint。

Part 07 · Scaling

放量：先算账，再决定要不要放

16GB 统一内存的边界在哪，训一个 125M 要多久，什么规模值得做 —— 这一部分全是算术，但算错一步就是三周白干。

07.16ND：一条公式算完所有算力

训练总计算量的近似公式只有一条：

FLOPs ≈ 6 × N × D N = 参数量，D = 训练 token 总数。系数 6 = 前向 2 + 反向 4

系数 6 的来历在 Part 03 拆过：每个参数在前向参与一次乘加（2 FLOPs），反向算输入梯度 2 FLOPs、算权重梯度 2 FLOPs。合计 6。

本机有效算力：Apple Silicon M4 的 16 核 GPU 理论峰值 fp32 约 4.6 TFLOPS、fp16 约 9.2 TFLOPS。实际训练按有效 3 TFLOPS 算（相对 fp32 峰值 65%，这是 mlx 在中等规模矩阵上的典型水平）。这个系数很重要 —— 用理论峰值估算，结果会乐观 1.5 倍，一周的计划变成十天。

Chinchilla 不是必须遵守的定律

20 token/参数 是 2022 年在特定算力预算下得出的「等算力最优」。它的前提是「算力固定，问参数和数据怎么分」。

如果你的目标是拿一个好用的模型而不是「用固定算力得到最低 loss」，那么训得更久（超过 20 token/参数）通常更划算 —— 因为推理成本与参数量成正比，与训练 token 数无关。这就是 Llama 系列用 200 token/参数 甚至更多的原因。

小模型上更实际的原则：数据量到你能弄到的上限为止。10M 模型训 1B token（100 token/参数）在 5.6 小时内完成，几乎肯定比训 200M 更好。

16GB 里能装多大，取决于四块之和：

项公式125M 模型（fp32 + Adam）
权重4N500 MB
梯度4N500 MB

激活那块是估算里最容易错的一项：反向传播要保存前向的中间结果，每层大约存 5–10 个与 [B, T, d] 同形的张量，加上注意力矩阵 [B, h, T, T]。系数 40 是「每层每元素约 10 个张量 × 4 字节」的粗估。

结论：125M 在 16GB 上是安全的（约 5GB），还有余量做更大的批或更长的上下文。真正卡住的从来不是内存，是时间。这也解释了为什么很多人用 Mac 训小模型感觉「很顺」—— 因为瓶颈在别处。

07.2决策：什么时候该从零训，什么时候不该

技术上能做，不等于应该做。下面这棵树的每个分支都给一个判据，不是「看情况」。

第一问：需要从零训吗

三个条件同时成立才值得：

条件判据不成立时该做什么
目标领域与现有模型差距大现成模型在你的测试集上 bpb 比随机基线好不到 20%用微调，别从零训
有 ≥ 20 token/参数的领域数据10M 模型需 ≥ 200M token（约 3 亿字）数据不够，从零训必然欠拟合
需要完全控制（结构、分词、许可）有明确的下游约束没有约束就是没有理由

第二条是最常被低估的。10M 参数看起来很小，但按 20 token/参数 需要 2 亿 token。大部分个人项目的领域语料在千万 token 量级 —— 差一个数量级。这时候从零训出来的模型，效果一定不如在这个领域上微调一个现成的小模型。

反过来说，如果你的目标是学习而不是产出可用模型，那第一条和第二条都可以不满足 —— 你就是要亲手跑一遍。这时候正确的做法是把规模压到最小：0.05M 参数、1 万 token、几秒钟一轮。学习效率与规模无关，与迭代次数有关。

第二问：规模选多大

按「你有多少数据」倒推，而不是按「你想要多大模型」正推：

可用 token 数对应参数量（20 token/参数）本机时间适用
10M0.5M分钟级学链路、验证想法
100M5M半小时小型领域模型
1B35–50M1 天推荐的起跑点
10B125M3–4 天（按 80 token/参数）上限，需一周不间断

第三行是推荐起点：1B token、35–50M 参数、一天。理由有三个 —— 数据量对个人项目是可获得的（约 15 亿字），时间在「能等」的范围内，模型大到能看出真实能力（不只是背训练集）。

第四行的数字有个细节：10B token 配 125M 参数是 80 token/参数，超过 Chinchilla 的 20。这不是错 —— 如上一节所说，数据充裕时多训更划算。但 10B token 的清洗成本本身就很高，实际很少有人做到。

第三问：什么时候停

三个停止信号，任一出现就停，不要「再训一会儿看看」：

信号判据说明
验证 bpb 连续 N 次评估不降N = 总评估次数的 20%过拟合开始，再训只会更差
训练 bpb 已低于验证 bpb 的 40%gap 过大模型在背，不在学
预算耗尽算力或时间到顶这是最常见的真实原因，不丢人

第一行的 N 不要设太大：本教程的 overfit 演示里，验证最低点出现在 step 5 / 400，也就是总步数的 1.25%。如果你每 50 步评估一次，会完全错过它。评估频率要密于「可能的最优点间距」，这一点在小数据上尤其致命。

一张纸的结论

学习目的：0.05M 参数、1 万 token、秒级迭代，先把 Part 01–05 跑通三遍。

产出目的：1B token、35–50M 参数、一天训练；数据先过 Part 02 的四项检查；评测用 bpb + 随机基线 + 人工通读。

不要做：在 16GB Mac 上训 125M 以上。不是不能，是收益/时间比不划算 —— 同样的时间用来把数据从 1B 提到 5B，效果通常更好。

算一下新的参数量：V·d = 8000×512 = 4.10M，每层 4d² + 3·d·ff + 2d，其中 ff = int(8/3×512/32)×32 = 1376，得 1,048,576 + 2,113,536 + 1024 = 3,163,136，8 层合计 25.3M，总计 29.4M。想再往上加就动 d 到 576 或 L 到 10。

放大时必须一次只改一个维度，并且用 Part 06 的消融账本记下来。同时改 d、L、T，出问题时无法归因 —— 这是从零训练最常见的返工原因。

三件比调参更值得做的事

一、把数据从 1B 提到 5B。在 16GB 机器上，数据量的边际收益远高于参数量的边际收益。同样的训练时间，更多数据几乎总是更好。

二、把评测做扎实。Part 06 的五条规则里，最容易省也最致命的是「测试集完全不参与决策」。省下这一步，后面所有结论都不可信。

三、跑三个种子。小规模训练的种子噪声可以到 ±0.05 bpb，足以让「改进 2%」变成噪声。三个种子取中位数，成本只多两倍，可信度提升一个量级。
